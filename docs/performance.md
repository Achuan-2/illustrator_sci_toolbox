# 大文档后台同步优化（更新至 2026-11-07）

插件开启后，主面板原本每 400 ms 调用一次 `syncZoomTracker`。每轮都会重建 `Document.tags` 索引，即使文档没有放大图或图稿完全没有变化。原生测试确认，这个集合的查询成本会随普通图稿数量增加，不能只按标签数量估计开销。

现在主面板调用 `syncSelectedZoomTracker`。打开文件、切换文档和选择对象时，只记录当前选区中带放大图关联标签的对象及其父级；选择放大图内部的裁剪子项、或比例尺的原图包装组，也能识别所属关联。普通对象直接返回，不发现文档、不遍历所有已知放大图、不修改图稿。

只有此前观察到的关联原图、区域框或放大图发生移动、缩放或删除时，才首次发现文档中的关联并建立 UUID 索引。首次绑定使用操作前的选区边界，不在打开文件或单纯选择时补画辅助线。取消选择后仍检查上一选区一次，避免漏掉最后的移动或删除。首次操作的历史快照也保留操作前的选区状态，沿用原有撤销／重做逻辑。

没有制作放大图时，不需要先扫描一次来确认“没有放大图”。已有放大图但没有操作关联对象时，也不再定期检查全文档。编辑器开始、确认、取消的 CEP 通知只使原登记失效并重新记录选区，不立即同步图稿；下一次相关操作再核验对象。

每个文档的 UUID 索引仍按原生文档实例区分，同名文件也独立。实际同步通过 UUID 核验成员身份，不能直接凭陈旧引用修改图稿；UUID 失效、对象被替换、新关系或撤销历史变化时恢复完整发现。旧版宿主不支持 UUID 时，仅在实际同步中使用标签发现。关联标签随 AI 文件保存，内存索引在脚本重载或文件重开后按需重建。

主面板尝试与 Adobe AIHostAdapter 握手；收到响应时，监听图稿选区／修改、撤销和重做通知，取消空闲轮询。事件先合并再检查选区，已有请求执行时最多保留一次后续检查。无法握手时，以至少 400 ms 的间隔轻量检查当前选区；因此兼容模式仍有宿主调用，但没有启动时或空闲时的文档发现。查询很慢时继续自适应延长间隔，后台请求让位于前台命令，隐藏面板或关闭自动更新时暂停调用。

本机 Illustrator 30.8.2 的适配器握手未收到响应，当前原生验证使用选区兼容路径。原生事件路径通过模拟 CEP 验证，未声称已在本机实际启用。未选中的对象由其他脚本修改，或兼容模式下在两次检查之间快速完成选中与修改、未观察到操作前状态时，不保证立即联动；普通外层组未携带关联标签时，不递归搜索其全部子项。

比例尺面板仍沿用原有的按选区检查及至少 350 ms 的间隔。下列较早的空闲缓存、UUID 对照数据保留为历史测试记录；它们衡量旧同步入口，不代表现在的选区入口或打开文件耗时。

## 2026-11-06：空闲缓存的原生对照

Illustrator 2026，版本 30.8.2。在同一个临时文档中比较修改前提交 `d4848ea` 和当时的空闲缓存版本，测试结束后关闭临时文档并确认文档数量恢复。以下是预热后的单次宿主脚本平均耗时，不包含 CEP 往返时间，也不等于打开文件耗时或 CPU 占用率。

| 场景（约 5,000 个普通对象） | 修改前 | 修改后 |
| --- | ---: | ---: |
| 没有放大图，空闲 | 1.240 ms | 0.013 ms |
| 1 个放大图，空闲 | 1.848 ms | 0.193 ms |
| 21 个放大图，空闲 | 37.109 ms | 5.596 ms |

21 个放大图的空闲样本各 20 次，修改后 P95 为 6.646 ms。该场景强制重新发现的平均耗时为 34.414 ms（5 次），移动原图并更新关联的平均耗时为 95.377 ms（10 次）。空闲样本只计缓存有效期间的查询；长期平均仍需计入低频发现的开销。大量图像、深层组、字体和宿主负载会改变结果，不能从这个临时文档推断所有真实文件的速度。

复现命令：

```powershell
./tests/illustrator-performance.ps1 -LegacyRevision d4848ea -ArtworkCounts 0,5000 -ReportPath dist/performance-comparison.json
```

性能脚本同时确认了原生标签父对象、原图移动时放大图输出位置保持不变，以及比例尺自动保存。原始数据位于本地 `dist/performance-comparison.json`，未纳入版本控制。

## 2026-11-07：UUID 索引的原生验证

同一宿主版本、约 5,000 个普通对象和 21 个放大图时，按 UUID 读取关联索引平均 3.542 ms（20 次，P95 4.201 ms），完整发现并建立索引平均 35.762 ms（5 次）。这两项只比较索引读取，不代表图稿重绘或完整同步速度。完整同步仍需读取边界、维护裁剪及辅助线，空闲缓存已有的边界检查开销也仍然存在。

测试通过仅用于验证的全文档发现计数器，确认重复 UUID 索引查询的全文档扫描次数为零。原生测试还确认复制对象获得不同 UUID、保存并重开临时 AI 文件后原 UUID 可定位、21 个关联全部恢复，以及重开后的 UUID 索引复核也不再扫描。旧文档句柄在关闭后连身份比较都可能抛出异常，已在身份判断和索引清理中处理。

原始数据为本地 `dist/zoom-uuid-performance.json`。复现命令：

```powershell
./tests/illustrator-performance.ps1 -LegacyRevision ea8fab4 -ArtworkCounts 0,5000 -ReportPath dist/zoom-uuid-performance.json
```

脚本在独立临时目录保存 AI 测试文件，关闭后清理该目录及 Illustrator 生成的临时文件，并恢复原活动文档。保存重开的结果仅代表本机 Illustrator 30.8.2；索引始终在新文件实例中重新建立，不依赖所有宿主版本都保留相同 UUID。

## 2026-11-07：按操作触发的原生验证

`./tests/illustrator-demand-sync.ps1` 在独立临时文档中生成 5,000 个普通对象和一个放大图。通过仅用于测试的完整发现计数器，确认打开后保持原图选中、重复空闲检查时扫描次数为零；首次移动原图后只完整发现一次，区域框跟随且放大图输出保持原位；取消选择后的最终移动仍会更新；随后操作普通对象不会再发现关联；删除选中的放大图会清理关联图稿。结束后关闭临时文档并恢复原活动文档及文档数量。

本机原生结果记录在 `dist/zoom-demand-native.json`。这验证了宿主的按需入口，未包含真实大文件的打开时间、CEP 往返或事件适配器在原生宿主中的可用性。

## 验证边界

自动测试新增打开／单纯选择零文档发现、首次原图／区域框／放大图内部子项操作、取消选择后的最终更新、删除清理、首次操作的撤销／重做，以及原生事件与兼容路径的调度、合并、重试和清理。原有 UUID、陈旧句柄、编辑器保护、历史恢复、队列和面板回归继续保留。面板测试使用编译后的 Svelte 产物及模拟 CEP 适配器。

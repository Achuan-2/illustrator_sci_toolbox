# 大文档后台轮询优化（2026-11-06）

插件开启后，主面板原本每 400 ms 调用一次 `syncZoomTracker`。每轮都会重建 `Document.tags` 索引，即使文档没有放大图或图稿完全没有变化。原生测试确认，这个集合的查询成本会随普通图稿数量增加，不能只按标签数量估计开销。

现在先使用缓存中的关联对象检查状态。没有变化时不读取全文档标签；检测到几何、关联标签或撤销标记变化后，先重新读取真实文档，再进行更新和历史恢复。缓存只用于跳过空闲查询，不能作为修改图稿的依据。撤销删除可能恢复缓存索引中已经不存在的对象，因此还会独立检查历史锚点的标记值。

主面板收到放大图编辑器开始、确认和取消的 CEP 通知时，会强制刷新索引。为覆盖粘贴、外部脚本以及遗漏通知，正常每 5 s 重新发现一次；索引查询很慢时，这个间隔会延长，最长 30 s。切换文档、关闭文档和重载宿主脚本都会使缓存失效。没有收到通知的新关联可能需要等待下一次发现。

放大图与比例尺的后台轮询均改为上一轮完成后再计时，间隔至少分别为 400 ms 和 350 ms。慢查询会额外等待其耗时的 9 倍，最长等待 30 s；编辑器通知可以提前唤醒放大图轮询。后台请求遇到已经排队的用户命令时直接跳过，避免在用户操作后面堆积查询。隐藏或折叠面板时继续暂停后台宿主调用。

## 本机原生对照

Illustrator 2026，版本 30.8.2。在同一个临时文档中比较修改前提交 `d4848ea` 和本轮代码，测试结束后关闭临时文档并确认文档数量恢复。以下是预热后的单次宿主脚本平均耗时，不包含 CEP 往返时间，也不等于打开文件耗时或 CPU 占用率。

| 场景（约 5,000 个普通对象） | 修改前 | 修改后 |
| --- | ---: | ---: |
| 没有放大图，空闲 | 1.240 ms | 0.013 ms |
| 1 个放大图，空闲 | 1.848 ms | 0.193 ms |
| 21 个放大图，空闲 | 37.109 ms | 5.596 ms |

21 个放大图的空闲样本各 20 次，修改后 P95 为 6.646 ms。该场景强制重新发现的平均耗时为 34.414 ms（5 次），移动原图并更新关联的平均耗时为 95.377 ms（10 次）。空闲样本只计缓存有效期间的查询；长期平均仍需计入低频发现的开销。大量图像、深层组、字体和宿主负载会改变结果，不能从这个临时文档推断所有真实文件的速度。

复现命令：

```powershell
./tests/illustrator-performance.ps1 -LegacyRevision d4848ea -ArtworkCounts 0,5000 -ReportPath dist/performance-comparison.json
```

性能脚本同时确认了原生标签父对象、原图移动时放大图输出位置保持不变，以及比例尺自动保存。原始数据位于本地 `dist/performance-comparison.json`，未纳入版本控制。

## 验证边界

自动测试覆盖空闲索引复用、定时重新发现、编辑器强制刷新、同名文档切换、关闭文档、慢请求不重叠、后台查询避让用户命令，以及放大图移动、删除、撤销和重做的模拟宿主回归。面板测试使用编译后的 Svelte 产物及模拟 CEP 适配器。

本机 `illustrator-zoom-undo-com.ps1` 的原生撤销检查未通过；修改前 `d4848ea` 对照也出现失败，原因尚未定位，因此不将原生撤销和重做列为已通过。未使用用户实际出现卡顿的大文件进行 GUI 验收，也未验证旧版 Illustrator 的实际性能。
